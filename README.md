# ChatBox 项目说明与使用教程

ChatBox 已在 R003（2026-10-11，Asia/Shanghai）导入现有 QQ-Agent，作为后续改造基线。原项目完整复制到本仓库的 `QQ-Agent/` 子目录，原业务代码、素材、文档、依赖和本地运行数据均保持复制时内容；本轮没有开始功能改造，也没有启动这个副本。

当前基线是 QQ 群聊/私聊 AI 机器人：OneBot v11 协议端连接 QQ，Node.js 后端负责消息存档、模型与工具调用，原生网页提供管理界面，Electron 提供桌面窗口和托盘。`QQ-Agent/package.json` 声明版本 `0.5.0-alpha`，界面显示 `v0.5alpha`。微信接入及 ChatBox 后续改造需求仍待明确，目录名称不能作为微信功能已实现的依据。

**本机完整副本与 GitHub 源码不是同一种交付。** 本机已完整复制 385 个文件、62 个目录，共 425,663,251 字节；逐文件 SHA-256 差异为 0，源目录复制前后没有变化。Git 只交付业务源码、素材、测试和原文档；`QQ-Agent/data/`、`QQ-Agent/node_modules/`、`QQ-Agent/snowluma/` 等运行数据和第三方运行时通过根目录 `.gitignore` 排除。因此，从 GitHub 新克隆的项目需要另装 Node.js/依赖，并补齐协议端后才能运行。

本说明书面向第一次接触项目的使用者和准备二次开发的程序员。以下功能与教程根据当前源码整理；本轮复制核验不等于真实 QQ、模型连通性或桌面运行已经验收。

## 3. 完全不懂 Git 时，可以先这样理解

Git 用来记录文件的不同版本。每次“提交”（`commit`）相当于给一组文件改动保存一个可追溯的版本；“推送”（`push`）把本地已有的提交上传到 GitHub；“拉取”（`pull`）把 GitHub 上的新提交下载并更新到本地。

这三件事有区别：保存文件不会自动提交，提交不会自动上传，上传也不表示程序已经经过运行验证。本项目要求 AI 在每轮实际开发完成必要验证和文档更新后自动提交并推送，这是开发规则，需要实际执行命令才能完成。

`origin` 是此项目给远程仓库起的名称；`main` 是当前本地分支；`origin/main` 是 Git 在本地保存的远端主分支状态。后者需要通过 `git fetch` 或 `git pull` 刷新，不能只看旧记录就判断 GitHub 此刻一定没有新变化。

本项目在 Windows 上默认使用 PowerShell 7（`pwsh.exe`）；仅在任务确实依赖 Windows PowerShell 5.1 兼容功能时使用 5.1，并解释例外。下面的命令在 PowerShell 中运行。代码块里的每一行是一条命令，按顺序执行即可；不要把终端输出当成下一条命令粘贴。

### 3.0 第一次使用：检查或安装 Git

在 Windows 开始菜单搜索并打开 PowerShell，输入：

```powershell
git --version
```

如果看到 `git version ...`，说明 Git 已经可用，直接继续第 3.1 或 3.2 节。若提示无法识别 `git`，按下面步骤安装：

1. 打开 [Git 官方 Windows 安装页面](https://git-scm.com/install/windows)。在 `Standalone Installer` 区域选择安装程序：通常的 x64 电脑选择 `x64 Setup`，ARM 电脑选择 `ARM64 Setup`；电脑类型可在 Windows 设置的“系统 → 关于 → 系统类型”查看。
2. 双击下载的安装程序，按向导完成安装。第一次使用可保留默认选项；安装过程出现系统授权提示时，确认运行的是刚从官方页面下载的安装程序。
3. 安装完成后关闭并重新打开 PowerShell，再运行 `git --version`。显示版本号后再执行后续下载命令。若使用开发工具的内置终端，也需要重新打开终端，必要时重开该开发工具。

也可以按该官方页面提供的方式，在已支持 `winget` 的电脑上执行：

```powershell
winget install --id Git.Git -e --source winget
```

若提示找不到 `winget`，使用上面的安装程序方法即可。这里提供安装说明，不会自动在你的电脑上安装软件。

### 3.1 已经在当前主开发电脑上：直接打开现有仓库

当前项目已经位于 `D:\开发\WeChat aibox`，不要在这个已有项目目录里再次执行 `git clone`。

打开 PowerShell 后执行：

```powershell
Set-Location -LiteralPath 'D:\开发\WeChat aibox'
git --version
git status
git remote -v
git branch -vv
```

各命令的作用与正常结果：

1. `Set-Location` 切换到项目文件夹；路径里的空格由引号保护。
2. `git --version` 显示 Git 版本，说明命令可用。如果提示找不到 `git`，先按第 3.0 节安装并重新打开 PowerShell。
3. `git status` 显示当前分支和未提交改动。工作区干净时通常会出现 `nothing to commit, working tree clean`。
4. `git remote -v` 中的 `origin` 应指向 `https://github.com/wraaaaaa/ChatBox.git`。
5. `git branch -vv` 的当前分支前面有 `*`，应为 `main`，并显示它跟踪 `origin/main`。

如果结果与上述目标不一致，保留现有文件，先根据实际 Git 状态处理问题。不要为“重来一遍”而删除 `.git` 或项目文件。

### 3.2 换一台电脑：下载到一个全新的目录

前提是电脑上能够执行 Git 命令，并且所选父目录已经存在。以下示例把仓库下载成 `D:\开发\ChatBox`，要求这个目标目录尚不存在；它与当前主开发窗口使用的目录是两个独立的工作副本。

```powershell

git clone https://github.com/wraaaaaa/ChatBox.git ChatBox
Set-Location -LiteralPath 'D:\开发\ChatBox'

```

`git clone` 会创建 `ChatBox` 文件夹、下载文件，并建立 Git 版本记录。下载完成后，先阅读三份项目文档。不同电脑上的本地改动不会实时共享，需要通过提交、推送和拉取同步。

如果 `D:\开发` 不存在，可选一个自己已经建立的文件夹，并相应修改示例路径。如果目标 `ChatBox` 文件夹已经存在，先确认它是什么内容；不要把现有文件夹删除来迎合示例命令。

只想阅读说明书的人也可以直接打开 [GitHub 项目页面](https://github.com/wraaaaaa/ChatBox)，点击 Markdown 文件查看，无须启动应用。

### 3.3 更新一个已有工作副本

先进入自己的项目目录，检查本地是否有未提交改动：

```powershell
Set-Location -LiteralPath 'D:\开发\WeChat aibox'
git status
git branch -vv
```

确认工作区干净、当前为 `main` 且跟踪 `origin/main` 后执行：

```powershell
git pull --ff-only
git status
git log -5 --oneline
```

`git pull --ff-only` 只接受可以直接接上的远程更新。如果本地和远端已经产生不同的提交，它会停止并提示无法快进，便于先检查差异。`git log -5 --oneline` 显示最近五条提交，帮助确认取到了什么版本。

如果 `git status` 显示自己正在修改文件，先处理这些改动再更新。如果出现分支分叉、冲突或登录失败，记录终端实际提示并处理原因，不要使用强制推送或丢弃文件来跳过问题。

### 3.4 判断提交是否真的上传

在 Git 命令成功完成后，可执行：

```powershell
git fetch origin
git rev-list --left-right --count HEAD...origin/main
git status
```

在当前 `main` 分支上，第二条命令返回 `0 0` 表示本地提交与刚获取的远端 `main` 没有差异。第一项非零表示本地有远端没有的提交，第二项非零表示远端有本地没有的提交。还可以在 GitHub 项目页面核对最新提交及文件内容。

这个核对证明的是版本同步情况；QQ-Agent 能否在你的配置和环境中运行，仍需要另外验证。

## 4. 如何准备、启动和日常使用


每条应显示版本号；命令找不到时，完成安装后重新打开终端。本轮验证使用系统 Node.js `v24.14.1`；这不是对所有 Node.js 或 Windows 版本的兼容承诺。

新克隆副本可以按包声明安装依赖：

这个安装流程本轮未执行，也没有锁文件保证版本完全相同。若提示包版本不存在、下载失败或权限错误，按实际报错核对包声明、网络和目录权限，不能将安装尝试写成成功。重新安装本机便携副本的 Electron 可能覆盖其 `default_app.asar` 无参数欢迎页补丁；当前完整副本无需先运行 `npm install`。

QQ 接入还需要独立 OneBot v11 协议端。可依其发行与许可要求补齐 SnowLuma 至 `QQ-Agent/snowluma/`，或使用已运行的外部 OneBot v11 正向 WS + HTTP 服务，在设置里填写真实地址和令牌。SnowLuma 是独立项目，按其自己的 EULA、隐私和许可处理。GitHub 源码缺少它时，不能把目录已存在或网页能打开当作 QQ 接入已经就绪。

### 4.2 桌面启动、无窗口启动与停止

在本机完整副本中，进入 `QQ-Agent` 后执行源码实际支持的命令：

```powershell

```

也可双击同目录的 `启动QQ机器人.bat`，它调用包内 Electron。启动会读取已有配置和积压消息，可能恢复提醒、调用模型、连接协议端并发送 QQ 消息；不要把真实启动当成无副作用测试。原实例与副本不要同时接同一账号和协议端，副本的单实例锁不应被当作跨安装目录的隔离保证。

对已成功安装依赖的新克隆副本，可在它的 `QQ-Agent` 目录运行 `npx electron .`；本轮未实测该安装和启动流程。根包没有 `scripts`，**不能使用原 README 历史段落中的 `npm start`、`npm run server` 或 `npm test`**。

正常预期是出现 QQ Agent 窗口，顶栏显示 OneBot、当前模型和用量状态，主页包含“会话、存档、记忆、用量、设置”。本地 HTTP 默认 `127.0.0.1:3210`，被占用时会尝试后续端口；以启动日志或 Electron 实际加载地址为准，不能固定假设总是 3210。

无窗口入口同样会启动真实后端：

```powershell
# 已有系统 Node.js 时，在 QQ-Agent 目录执行
node .\src\server.js
```

完整副本也可使用 `& .\snowluma\node.exe .\src\server.js`。无窗口入口没有 Electron 单实例锁，不要重复启动。浏览器访问日志中给出的本机地址；结束时在该终端按 `Ctrl+C`。桌面端应右键系统托盘图标 →“退出”；窗口右上角 X 可能询问关闭方式或缩到托盘，关窗不等于退出。退出 Agent 后若要停止协议端，也应在其自身控制台正常停止，不要结束电脑上所有 `node.exe` 或 `electron.exe`。

### 4.3 第一次配置 QQ 接入、模型和名单

完整副本继承源目录数据，不保证是首次空配置。先确认显示的账号、端点和白名单是自己希望继续使用的内容；不要为获得空界面随意删除 `data/` 或协议端登录目录。

1. 打开“设置 → SnowLuma · OneBot”，按需要指定 SnowLuma 目录和是否自动拉起；或者先在独立协议端完成 QQ 登录与 OneBot 网络配置。
2. 将协议端的 WS 服务填入应用 `wsUrl`，HTTP API 服务填入 `httpUrl`。源码默认分别为 `ws://127.0.0.1:3001` 与 `http://127.0.0.1:3000`；令牌必须与协议端一致，HTTP 可以用单独令牌。保存后完整退出并重启应用使地址变更生效。
3. SnowLuma 控制台地址按其 `config/runtime.json` 与日志读取，应用回退端口为 5099。使用它实际生成的凭据登录，完成它要求的授权与 QQ 登录；不要照历史文档把示例密码当作当前密码。
4. 返回应用，确认顶栏 OneBot 已连接，且就绪提示能够识别正确 QQ 账号。仅 WS 已连不代表 QQ 已登录或消息事件能够到达。
5. 打开“设置 → 模型 API”，点击 DeepSeek、GLM、GPT 中实际要用的预设，选择模型，填写自己的 API Key，点击“保存并使用”；自定义兼容端点在“其他”中填写 Base URL、Key 与准确模型 ID，添加模型后选择使用。示例自定义地址可写 `https://api.example.com/v1`，示例 Key 用 `YOUR_API_KEY`，这些占位内容不能真的调用服务。
6. 按需点“测试连通性”，阅读实际结果。模型接入操作立即保存；温度、工具轮数、思考和图片等高级参数修改后需点“保存设置”。测试会访问指定服务，费用与权限由服务决定。本轮没有调用真实外部模型。
7. 打开“设置 → 聊天白名单”，从群列表勾选/填写目标群号，添加需要的私聊 QQ 号，保存设置。默认名单为空且 `allowAllWhenEmpty: false` 时不会接入聊天；拒绝名单和屏蔽设置仍会影响实际接收。
8. 使用指定测试群/私聊验证：先在“存档”选择目标，手动发送一条自己的测试文字；确认 QQ 收到后再在 QQ 中 @ 机器人，并在“会话”检查触发、工具发送和结果。这些操作是真实发送，应使用自己确定的测试目标；本轮未执行。

没有回复时，依次查：是否暂停、OneBot/QQ 状态、名单、模型配置、响应档位、是否被禁言、最近会话错误和发送日志。`noreply` 表示一次正常运行没有发言，`error`/`aborted` 需查具体原因，不能把所有没有发言都当成失联。

### 4.4 消息、会话与响应控制

“会话”中选择一次运行，查看唤醒原因、输入上下文、思考/工具步骤、发送结果和 token 用量；“存档”选择群或私聊查看历史，手动输入后发送；“用量”按页面筛选查看聚合与明细。聊天消息与模型运行分别保存，不要把一个会话误认为整个群聊历史。

在“设置 → 聊天设置”调响应滑条：低档主要 @，再加关键词，中间档概率响应，高档全响应；需要单独设置群时关闭统一档位，展开自定义群聊档位。未命中触发的群消息仍会留档并标记已读，但不创建模型运行。私聊不受群聊概率档位限制，仍须通过名单、模型、暂停等条件。

同页可调整上下文条数、发送间隔和限频，配置关键词、管理员、禁言回应、表情包及主动搭话。主动搭话源码默认关闭，打开后可能在没有新消息时发起模型处理。顶部“暂停”停止处理，恢复积压策略由 `resumeBacklogMode` 决定：默认 `tier` 按档位，`force` 强制补处理；补处理不保证模型一定发言。修改后点“保存设置”，再用指定测试聊天检查预期行为。

### 4.5 人设、印象、跨群记忆、提醒与风格

在“设置 → 人设”选择角色、编辑名称与规则，按页面控件导入/导出或创建自定义人设；高级选项默认折叠。切换角色后检查当前名称与对应记忆，不要假设所有角色、群聊和私聊自动共享记录；角色蒸馏与后台整理依赖配置的模型。

顶层“记忆”只管理聊天群友印象：选择聊天查看成员记录，按页面勾选或清空控件处理指定记录。“设置 → 记忆”展开后含三项：

| 子项 | 使用方法 | 记录处理边界 |
| --- | --- | --- |
| 跨群档案 · 长期记忆 | 调整整理、档案共享和独立模型，保存；查看记录摘要并点“查看和管理记录”在当前设置页展开详情 | “初始化记录”清空当前人设的档案、长期事件和表层记忆，不清空其他配置 |
| 定时提醒 | 打开提醒开关并保存；可让机器人在聊天中登记时间和事项，例如“明天下午 3 点提醒我开会”，也可在“查看和管理记录”内手工新建；检查时间、目标、重复规则并按需取消 | 自然语言登记和自然表达会调用模型；手工创建及原文直发可不调用模型；“初始化记录”清空提醒记录，实际投递仍需调度与 QQ 链路就绪 |
| 说话风格库 | 开启采样/蒸馏并保存；查看样本和已学规则，按页面添加、置顶或删除记录 | 采样来源须符合自己的数据范围；“初始化记录”清空样本与已学规则，不重置功能参数 |

手工创建提醒：进入“设置 → 记忆 → 定时提醒”，点“查看和管理记录”，在“新建提醒（手工）”填事项、时间（例如“30分钟后”）、目标会话和重复规则，点“添加”，在列表核对结果。目标列表为空时先确认已有可用聊天；缺内容、时间或目标时页面会提示补齐。提醒方式选择“直接复读提醒原文”可直接发送；启用“兜底直发”时，模型未配置或失败也可发送原文。设置修改后点“保存设置”。到时投递仍取决于运行状态、名单和 QQ 链路，本轮未验收真实投递。

初始化某类记录前阅读确认范围；运行或后台整理忙碌时后端可能拒绝操作，等相关任务结束后再处理。删除是实际数据操作，备份与取消确认是恢复误操作前的办法，不能把记录初始化用于日常测试。

### 4.6 搜索、图片、表情与梗库

“设置 → 搜索服务”选择 Bing 或其他内置服务；需要自定义端点时展开自定义搜索源，填地址、密钥和协议类型，添加并保存。模型可以通过搜索/网页读取工具取得结果；Bing 默认配置不要求 Key，但网络可用性和服务限制仍会影响结果。

“设置 → 搜图服务”选择图源，按需调整数量、图片大小、AI 图屏蔽和会话覆盖，自定义源添加后保存。聊天中可询问图片内容或要求找图；看图须开启“模型 API”的图片输入且模型实际支持视觉，发送图片还取决于 OneBot。图片下载和网页读取保留地址、重定向与大小检查；遇到被拦地址应核对来源，不能为一次失败全局放开内网。

表情采集和发送行为在“聊天设置”中调整；已有工具支持检索、备注、采集和发送表情及拍一拍。发送绑定当前聊天，群友不能通过提示模型任意更换目标。“设置 → 梗知识库”管理人工条目、Markdown 导入、注入及自动记梗，检查导入后的条目，再让模型在对应场景检索；B 站候选发现和其他联网功能都依赖真实外部服务，本轮未验证。

### 4.7 界面和桌面设置

顶栏“刷新页面”重载网页；“暂停背景/继续背景”控制视频背景；主题按钮依次切换暗、明、跟随系统和“？”四种模式，“？”模式保留特殊画面效果。“设置 → 桌面端”可配置主题、开机启动、关窗行为和刷新间隔。修改开机启动会影响当前 Windows 用户启动项，副本导入本身没有更改该设置或系统状态。减少动态效果和页面隐藏的处理已有源码，Electron 后台窗口的真实 GPU 消耗本轮没有测量。

后端源码更新后，使用托盘“退出”完整退出并重新启动；仅刷新页面不加载新的 Node.js 模块。前端修改也应刷新后实际检查页面和控制台错误。

| 路径 | 保存内容 | 分享与更新时的处理 |

最简单的本机完整备份是先正常退出 Agent 和它所属的协议端，再把 `QQ-Agent` 整个目录复制到独立备份位置。只备份用户数据时，也应保留整个 `data/` 和协议端 `config/`、`data/`；日志可供排查，但同样含私人内容。确认没有目录联接/符号链接并选用全新的备份目录后，示例：

```powershell
# 在程序和本项目协议端均正常退出后执行；修改目标为自己的新备份位置
Copy-Item -LiteralPath 'D:\开发\WeChat aibox\QQ-Agent' -Destination 'D:\备份\ChatBox-QQ-Agent-20261011' -Recurse
```

备份后抽查关键文件和数据是否存在。恢复时先退出目标实例，把目标现有目录另行保留，再从备份恢复到新的目录，核对账号、配置、版本和路径后只启动一个实例；不要把“覆盖全部”当作无损合并方案。恢复整个副本与只恢复数据要分开做，避免把新源码覆盖成旧版或同时运行两个连接同一账号的副本。

源码更新按第 3.3 节先查 Git 状态、退出实例并备份，再 `git pull --ff-only`，阅读本轮记录是否需要依赖/数据迁移，完整重启后验收。本轮没有数据迁移，也没有替换依赖、打包安装程序、Docker、Windows 服务或公网部署方案。默认监听 `127.0.0.1`；`server.token` 留空时 API 没有通用强身份认证，不应直接公开本地控制台。

根 `.gitignore` 不会删除本机副本，也不等于备份。它只让 Git 排除运行数据、依赖和协议端；推送前仍要检查本轮暂存内容，不能用 `git add -f` 绕过边界。换机仅 `git clone` 得不到旧密钥、QQ 登录态、聊天和记忆，须用自己保存的私有备份与运行时恢复。

### 4.9 完整初始化

“设置 → 关于 → 初始化全部内容”是实际清理操作，第一次确认展示范围，第二次必须输入“初始化”。确认后写入清理任务并完整重启；界面需等对应完成状态，HTTP 接受请求不表示已经清理完成。

它会清除整个项目 `data/` 和内置 SnowLuma 的配置、账号数据、日志，包括 API、供应商、白名单、人设、自定义设置、消息、会话、记忆、提醒、风格、梗库、表情缓存、用量和旧备份，恢复完整默认配置；程序、依赖、内置素材和内置人设保留。模型与接口变空，开机启动和协议端自动启动关闭。电脑 QQ 客户端自身登录文件不在清理范围；外部共享协议端、危险目录或链接路径会被拒绝。

需要保留的数据先按第 4.8 节备份。运行、整理、蒸馏、视觉扫描或桥接启动等忙碌状态可能拒绝初始化；取消确认不清理。失败时按界面与日志排查，清理任务可能在下次完整启动继续执行，不能在错误后假设所有数据已删除或自动恢复。本轮没有对真实副本执行初始化。

### 5.2 入口和消息调用链

桌面入口：`启动QQ机器人.bat` → `electron/main.js` → 设置数据目录与单实例锁 → `src/app.js` 的 `createApp()` → 核心 `start()` → HTTP 服务与 Electron 窗口。无窗口入口 `src/server.js` 使用同一后端。`createApp()` 本身会加载和恢复数据，不能只因为未调用 `start()` 就认定无副作用。

消息链：`src/onebot.js` 收事件 → `src/app.js` 过滤、解析 → `src/store.js` 去重与存档 → `src/orchestrator.js` 聚批、触发、并发、未读消费 → `src/prompt.js` 组装人设/历史/记忆 → `src/llm.js` 与 `src/openai-responses.js` 调模型 → `src/tools.js` 执行绑定当前聊天的工具 → `src/sender.js` 队列发送 → 会话/用量落盘 → SSE 推送到 `ui/app.js`。

每次模型运行重组上下文，但消息、记忆、人设、提醒和用量持续保存；“无状态”不表示没有数据，也不保证 token 成本严格固定。同一聊天一次模型运行，跨聊天并行受全局上限限制；运行中收到的新消息留为未读，结束后再调度。失败恢复、重试和部分发送会共同影响是否重复回复，不能只查一个重试分支就认定全链路恰好发送一次。

### 5.3 模块与配置来源

| 位置 | 主要职责 | 修改时需要沿着检查的关系 |
| --- | --- | --- |

## 8. 常见问题

**从 GitHub 下载后为什么找不到 Electron 或 SnowLuma？**

Git 上传源码、素材、测试和文档；依赖、协议端及真实数据被忽略。按第 4.1 节补齐运行环境后再启动。本机原样完整副本与新克隆副本不同，不能互相套用“免安装”。

**原 README 写的 `npm start` 为什么报 Missing script？**

当前包没有 scripts。完整便携副本使用第 4.2 节 Electron 命令或批处理；新安装副本可用 `npx electron .`，无窗口入口为 `node .\src\server.js`。历史文档保持原样，不能将其中缺失脚本当成真实入口。

**已经能连接微信了吗？模型和 QQ 链路本轮都测试了吗？**

微信接入未实现。本轮导入已有 QQ-Agent 并做复制/隔离检查，没有启动真实 Electron、SnowLuma、QQ 或调用真实外部模型；功能有源码不等于新位置真实运行已通过。

**OneBot 显示连接了，为什么仍没有消息或回复？**

检查 QQ 登录信息、WS 消息事件、HTTP action、令牌、名单、暂停、响应档位、模型权限及会话错误。WS 连接、QQ 登录、入站消息和出站发送是不同环节，需逐个核对；不要根据历史文档把 WS/HTTP 端口对调。

**复制后界面不是空白首次配置，是不是复制错了？**

本次要求原样复制，所以继承原数据。原目录保留，副本文件已逐个哈希核对。需要清理时先明确范围并备份，用已有确认流程；本轮没有重置或脱敏本机副本。

**关窗、暂停、刷新分别影响什么？**

关窗可能缩托盘，进程仍在运行；暂停影响模型调度，恢复积压按设置处理；刷新只重载网页。完整停止用托盘“退出”，后端源码更新后必须完整重启。

**另一位 AI 怎样接上进度，自动 push 为何不是实时同步？**

提供最新版 `VIBECODING.md`，接手时读取根三文档、导入目录说明及实际 Git/源码。规则保存在文件里，恢复后仍须主动重读；自动 push 是每轮必要验证和文档更新后的实际提交/推送流程，没有后台文件同步服务。

**`git push` 失败或出现 `nothing to commit` 怎么处理？**

推送失败保留本地提交，查看认证、网络、远端差异或保护规则的实际错误，正常解决后重试；不强推。`nothing to commit` 通常表示没有新变化，若本轮应有文件则查保存位置、暂存状态和忽略规则，不为纯检查制造空提交。
